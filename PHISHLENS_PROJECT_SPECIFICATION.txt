1. EXECUTIVE SUMMARY & PROBLEM STATEMENT
--------------------------------------------------------------------------------
India loses over ₹1,750 Crore annually to digital financial fraud: fake KYC
updates, electricity disconnection threats, digital arrest extortion, and UPI
refund traps. Existing government countermeasures (such as Chakshu and the 1930
National Cyber Crime Reporting Portal) operate as post-incident reporting
registries—victims can only lodge complaints AFTER money has already been stolen.

PhishLens is an active, PRE-TRANSACTION INTERCEPTION LAYER. Before a citizen
enters an OTP, submits net banking credentials, or inputs a UPI PIN, PhishLens
scans the communication across 3 parallel AI vectors + 1 specialized financial
vector:
  1. Domain & URL Intelligence (Atharv)
  2. Sender Identity & TRAI DLT Verification (Avni)
  3. UPI Virtual Payment Address (VPA) Deception Detection (Avni)
  4. Psycholinguistic Intent & Coercion Analysis (Vikas)

Signals are synthesized via a dynamic weighted scoring engine with non-linear
heuristic escalation overrides (Avika), rendering an Explainable AI (XAI)
verdict with bilingual (English + Hindi) citizen advisories and a 4-tier
intervention action (ALLOW, WARN_USER, BLOCK_TRANSACTION). The entire flow
is coordinated by an async FastAPI orchestrator and SQLite audit logger (Vansh)
and visualized on a React 18 cyber-defense dashboard (Yuvraj).

3. END-TO-END SYSTEM ARCHITECTURE
--------------------------------------------------------------------------------
1. Client Input: User or payment app submits message, link, or UPI prompt.
2. Ingestion: POST /api/v1/scan to FastAPI orchestrator (main.py).
3. Pre-Processing:
   - Extract URL using regex if not explicitly provided.
   - Detect input type: web_url, upi_handle, or text_message.
   - Check if UPI handle/deep-link signal exists in content or sender.
4. Parallel Agent Dispatch:
   - asyncio.gather(safe_url(), safe_sender(), safe_intent(), [safe_upi()])
   - Enforced 3.5-second supervisor timeout per agent via asyncio.wait_for().
   - Fail-safe shielding: agents return status="ERROR" with score=0.0 on crash.
5. Dynamic Synthesis (Scoring Engine):
   - Compute dynamic weights based on active/skipped/errored agents.
   - Evaluate non-linear heuristic escalation overrides.
   - Generate bilingual verdicts, top reasons, and structured evidence.
6. Async Audit Logging:
   - Non-blocking background task logs scan to SQLite.
   - Redacts 10-digit mobile numbers and OTPs.
   - Records SHA-256 payload hash and processing latency.
7. Frontend Render:
   - Frictionless allow for SAFE.
   - Warning banner for CAUTION.
   - Explicit confirmation for HIGH_RISK.
   - Full-Screen Hard Block Interception Modal for CRITICAL.


--------------------------------------------------------------------------------
4. THE 4-TIER DECISION MATRIX
--------------------------------------------------------------------------------
Score Range  | Risk Tier  | Verdict Category | Action Required   | UI Behavior
-------------+------------+------------------+-------------------+-----------------------------------
 0 – 24      | SAFE       | SAFE             | ALLOW             | Green confirmation banner
25 – 49      | CAUTION    | SUSPICIOUS       | WARN_USER         | Amber advisory, verify sender
50 – 77      | HIGH_RISK  | LIKELY_SCAM      | BLOCK_TRANSACTION | Orange persistent alert card
78 – 100     | CRITICAL   | LIKELY_SCAM      | BLOCK_TRANSACTION | Full-screen hard-block modal


--------------------------------------------------------------------------------
5. CRITICAL HEURISTIC ESCALATION OVERRIDES (NON-LINEAR)
--------------------------------------------------------------------------------
1. Double Whammy Escalation:
   - Condition: URL Risk >= 80 AND Sender Risk >= 80
   - Action: Composite Score <- max(Score, 92.0) -> CRITICAL / BLOCK_TRANSACTION

2. Personal GSM Bank Impersonation:
   - Condition: 10-digit GSM sender claiming bank/utility with urgency/KYC
   - Action: Composite Score <- max(Score, 88.0) -> CRITICAL / BLOCK_TRANSACTION

3. Active OTP / Credential Harvesting:
   - Condition: Demands OTP, UPI PIN, or NetBanking password under urgency
   - Action: Composite Score <- max(Score, 90.0) -> CRITICAL / BLOCK_TRANSACTION

4. Digital Arrest & Coercive Psychological Extortion:
   - Condition: Threatens police arrest, CBI inquiry, or court summons
   - Action: Composite Score <- max(Score, 82.0) -> HIGH_RISK / BLOCK_TRANSACTION

5. TRAI Certified Header Exemption (Safe Override):
   - Condition: Verified official TRAI DLT header with clean URL and no coercion
   - Action: Composite Score <- min(Score, 12.0) -> SAFE / ALLOW

8. HOW TO RUN & TEST
--------------------------------------------------------------------------------
Backend:
  cd backend
  python -m venv venv
  venv\Scripts\activate   (Windows) OR source venv/bin/activate (macOS/Linux)
  pip install -r requirements.txt
  uvicorn main:app --reload --port 8000
  API Docs: http://localhost:8000/docs

Frontend:
  cd frontend
  npm install
  npm run dev
  Web UI: http://localhost:5173

Run Test Suites:
  cd backend
  pytest tests/test_sender_agent.py -v   (Avni - 34 tests)
  pytest tests/test_upi_agent.py -v      (Avni - 5 tests)
